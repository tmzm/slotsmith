# Labels, locales and right-to-left

## Every string is a label

Each component takes a `labels` prop: a partial object that overrides any user-facing string, including accessible names that are never visible. Strings that depend on a value are functions.

```tsx
<Autocomplete
  options={cities}
  labels={{
    placeholder: "Choisir une ville",
    empty: "Aucun résultat",
    results: (count) => `${count} résultats`,
  }}
/>
```

The English defaults are exported (`defaultLabels` for the data table, `defaultAutocompleteLabels`, `defaultDatePickerLabels`, `defaultFileUploaderLabels`), which makes a good base for a translation file. The file uploader also takes `validationLabels` for its rejection messages.

## Locale packs

`slotsmith/locales/<code>` ships one file per language, each holding the labels of every component plus the plural and number formatting they need. A pack is a plain object; nothing needs a provider to use one directly:

```tsx
import { ar } from "slotsmith/locales/ar";

<DatePicker locale={ar} />;
```

## The provider

`SlotsmithProvider` sets the language for every slotsmith component below it, once, from the packs it is given:

```tsx
import { SlotsmithProvider } from "slotsmith/locale";
import { ar } from "slotsmith/locales/ar";
import { fr } from "slotsmith/locales/fr";

<SlotsmithProvider locale={language} locales={[ar, fr]}>
  <App />
</SlotsmithProvider>;
```

`useSlotsmithLocale()` reads the active tag and direction back, for an app that wants to set `lang` and `dir` on its own markup itself (the provider renders no element).

## String versus object

Every component's `locale` prop, and the provider's, takes `string | SlotsmithLocale`:

- **An object** (a pack, or one from `defineLocale`) is used as is — no provider needed.
- **A string** is looked up among the packs given to the nearest provider: the exact tag first (`ar-EG`), then a pack whose code is the bare language (`ar`), then any pack of the same language. No match means English labels, `Intl` formatting with that tag, and one development-only warning per tag (a tag whose language is `en` never warns, since there is no English pack to miss).

```tsx
// Registers ar and fr; "ar-EG" resolves to the ar pack, formatted for Egypt.
<SlotsmithProvider locale="ar-EG" locales={[ar, fr]}>
  <App />
</SlotsmithProvider>

// "ar-EG" with no provider, and no ar pack registered: English labels,
// Intl formatting for ar-EG, and one console warning in development.
<DatePicker locale="ar-EG" />
```

## `defineLocale`

A custom locale is typed with `defineLocale`, which fills in the direction when the tag's language is known to be written right to left:

```tsx
import { defineLocale } from "slotsmith/locale";

const ku = defineLocale({
  code: "ckb",
  table: { /* every DataTableLabels key */ },
});

<DataTable locale={ku} />;
```

Each component's section (`table`, `autocomplete`, `datePicker`, `fileUploader`, `fileValidation`) is optional, but a section that is present must have every key of that component's labels — the type checker enforces it, so a translation cannot ship half-finished. A section may also be a function of the active tag, which lets one pack serve every region of its language (the same Arabic text formats its numbers in Arabic-Indic digits for `ar-EG`). At runtime, a locale built by hand and missing a key added in a later release falls back to English for that one string; nothing throws.

## Precedence

For every string, in order: the `labels` prop wins, then the component's own `locale`, then the provider's `locale`, then the English default. A component's own `locale` replaces the provider's whole — languages are never mixed within one component.

```tsx
// Egyptian Arabic everywhere, except this one override.
<DataTable locale={ar} labels={{ empty: "لا توجد طلبات" }} />
```

## Locales and the date picker

The date picker takes a BCP 47 `locale` (a string or a pack). Month names, weekday names and the trigger's date format come from `Intl`, so there is nothing to translate there but the labels. The calendar grid itself is always Gregorian, even for tags such as `ar-SA` or `fa-IR` whose `Intl` default is the Hijri or Persian calendar — the day grid, month names, year and trigger text stay Gregorian in every locale. `weekStartsOn` defaults to the locale's own first day and can be set explicitly (`0` is Sunday, `6` is Saturday). Values stay locale-independent: the date picker's value is always a `YYYY-MM-DD` string.

```tsx
<DatePicker locale="ar-EG" weekStartsOn={6} labels={{ placeholder: "اختر تاريخًا" }} />
```

## Locales and the file uploader

The file uploader's slot context carries a `locale` field — the active BCP 47 tag as a plain string — so a replaced `Dropzone` or `List` slot can format file sizes the same way the fallback does.

## Locales from a Next.js Server Component

A pack holds functions (its plural- and number-dependent sections), so it cannot be passed as a prop from a Server Component straight to a client component — functions do not survive that boundary. Put `SlotsmithProvider` and the packs it needs in a client file:

```tsx
// app/providers.tsx
"use client";
import { SlotsmithProvider } from "slotsmith/locale";
import { ar } from "slotsmith/locales/ar";

export function Providers({ language, children }: { language: string; children: React.ReactNode }) {
  return <SlotsmithProvider locale={language} locales={[ar]}>{children}</SlotsmithProvider>;
}
```

and render it from the server layout with only serialisable props (`language` above, not a pack). A serialisable locale form that can cross the server/client boundary is deferred to a later release.

## Right-to-left

Put `dir="rtl"` on the page or on any ancestor. The stylesheet uses logical properties only, so every fallback mirrors without extra rules. Behaviour follows the visual direction too: the date picker reads the computed `direction`, swaps its previous and next controls, and moves to the next day on the left arrow key.

When replacing parts, keep to logical properties (`margin-inline-start`, or `ps-*` / `pe-*` in Tailwind) so the replaced parts mirror the same way.
