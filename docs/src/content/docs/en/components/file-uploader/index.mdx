The slotsmith FileUploader is a React file uploader. Drop or browse files, check them against your limits, preview images, and upload them with progress, retry and cancellation. Leave out the `upload` function and it is a picker that never touches the network. Every part is a slot you can replace.

## Overview

The demo below uses the fallbacks only, and its uploads are simulated in the page: nothing leaves your browser. Drop up to four images or PDFs, or press <kbd>Enter</kbd> on the drop zone to browse. Tick the box to make the next uploads fail, then retry them.

## Quick start

## Adapters

The file uploader works with any design system. Each slot takes a component, so a library's own surface, buttons, avatar and progress bar can replace the fallbacks while the queue, the validation and the previews stay the same. The [Adapters page](./adapters/) has ready slot maps for shadcn/ui, MUI, Chakra, Ant Design and Radix Themes, as examples of well-known libraries; the same approach works with your own.

## Accessibility

- **The drop zone** has `role="button"` and is in the tab order (`tabindex="0"`, or `-1` while [`disabled`](./api/#prop-disabled), with `aria-disabled`). It is named by the [`dropzone`](./api/#label-dropzone) label, "Add files" by default. A click, <kbd>Enter</kbd> or <kbd>Space</kbd> opens the file dialog. Dragging a file over it sets `data-dragging` and switches the title to the [`dropHere`](./api/#label-dropHere) label.
- **The file input** is a real `<input type="file">`, visually hidden but left in the accessibility tree and named by the same label. It is out of the tab order, because the zone and the Browse button open it, but Chrome exposes it as a second "Add files" button to a screen reader's browse mode; this is a known library issue. Its `accept` and `multiple` follow your props.
- **The Browse button** is a `<button type="button">` inside the zone, so it never submits a form. A button inside a `role="button"` element is a nested interactive control, which some screen readers announce poorly; this is a known library issue.
- **Progress** is a `role="progressbar"` with `aria-valuenow` (the percentage, rounded), `aria-valuemin="0"` and `aria-valuemax="100"`, named "Uploading" and the file name by the [`progress`](./api/#label-progress) label. See it in the [uploads guide](./guides/uploads/).
- **Each item's actions** are buttons named by the [`remove`](./api/#label-remove), [`retry`](./api/#label-retry) and [`cancel`](./api/#label-cancel) labels. The names do not include the file name, so a list of several files has several "Remove file" buttons; the button sits in the file's list item.
- **Image previews** are `<img>` elements with alt text from the [`preview`](./api/#label-preview) label ("Preview of photo.png"). Other files show a decorative glyph, hidden from assistive technology.
- **Refused files** are listed in a `role="status"` region with `aria-live="polite"`, and stay until the Dismiss button, named by the [`dismiss`](./api/#label-dismiss) label, clears them. The region appears with the first refusal, which some screen readers do not announce; later refusals are added to it and announced without interrupting. This is a known library issue. See the [validation guide](./guides/validation/).
- **Status changes** of an item (Uploading, Uploaded, Failed) are shown as text in the item and are not announced on their own.

## Limitations

<Note kind="limitation">
- One request per file. There are no chunked or resumable uploads, and a retry starts the file again from zero.
- No `name` prop: the file input has no name, so a plain HTML form does not send the files. Build the request yourself from `onFilesChange`, as the [picker guide](./guides/picker/) does.
- Files only: a dropped folder is not read file by file, and there is no paste from the clipboard.
- `accept` checks the file name and the MIME type the browser reports, not the file's contents. Check files on the server too.
- Previews are object URLs for images only. There is no cropping, resizing or compression before upload.
- A drop that misses the zone opens the file in the browser tab, unless you set [`captureWindowDrops`](./api/#prop-captureWindowDrops).
- Items restored from a URL have no size, so none is shown, and cannot be retried.
</Note>
