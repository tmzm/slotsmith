The slotsmith data table is a React table built on TanStack Table, with sorting, selection, pagination, tree rows, virtual rows and row reorder built in. Every part it renders is a slot: keep the fallbacks, or pass your design system's own components.

## Overview

The demo below uses the fallbacks only. Click a header to sort, shift-click a second header to sort by both, tick rows to select them, and change the page size under the table.

## Adapters

The table works with any design system. Each slot takes a component, so a library's own table, checkbox, button and select can replace the fallbacks. The [Adapters page](./adapters/) has ready slot maps for shadcn/ui, MUI, Chakra, Ant Design and Radix Themes, as examples of well-known libraries; the same approach works with your own.

## Accessibility

The table renders a real `<table>`, so screen readers announce rows, columns and headers. What the fallbacks add:

- **Sorting.** A sortable header holds a `<button>`, and its `<th>` carries `aria-sort` (`ascending`, `descending` or `none`). With `enableMultiSort`, shift-click adds a column to the sort.
- **Selection.** Each row and the header have a checkbox named by the `selectRow` and `selectAll` labels; the header checkbox is indeterminate while some rows on the page are selected.
- **Tree rows.** The expand toggle is a `<button>` with `aria-expanded`, named by `expandRow` or `collapseRow`.
- **Pagination.** The controls sit in a `<nav>` named by the `pagination` label. The previous and next buttons are named by `previousPage` and `nextPage`, and the page counter is an `aria-live="polite"` region, so a page change is read out. The page-size control is the slotsmith Autocomplete, a combobox named by the visible `rowsPerPage` text.
- **Loading and errors.** While loading, the root has `aria-busy="true"` and the skeleton rows are hidden from assistive technology. The error state has `role="alert"` and a retry button.
- **Row reorder.** Each drag handle is a `<button>` named by `reorderRow`, with `aria-describedby` pointing at hidden instructions (`reorderInstructions`) and `aria-pressed="true"` while it is lifted from the keyboard. A visually hidden live region (`role="status"`, `aria-live="assertive"`) reads each step with the `reorderLifted`, `reorderMoved`, `reorderDropped` and `reorderCancelled` labels, as positions such as "Position 2 of 5". In a tree table, a row with no visible sibling has its handle disabled.

## Limitations

<Note kind="limitation">
- `VirtualDataTable` ignores row reorder. See [virtual rows](./guides/virtual-rows/).
- A drop while the table is sorted reorders `data`, but the view stays sorted. See [row reorder](./guides/row-reorder/).
- No dragging between tables, no multi-row drag, and no moving a row to another parent. See [row reorder](./guides/row-reorder/).
- A custom `Row` slot must keep a stable identity. See [row reorder](./guides/row-reorder/).
</Note>
