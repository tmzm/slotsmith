For long lists, pass `virtual` to the data table with the virtualizer hook as `use`: it then renders only the rows in view, inside a scroll area with a sticky header. The hook is `useVirtualizer` from `@tanstack/react-virtual`.

The table holds 10,000 log lines, built from their index so every render gets the same ones. Scroll it, or sort by a column: only the rows on screen exist in the page.

## Install

`@tanstack/react-virtual` is an optional peer: you pass its hook in, so slotsmith itself never imports it, and a project that never windows a list does not need it.

```sh
pnpm add @tanstack/react-virtual
```

## The virtual option

`virtual` takes the hook as `use`, and three numbers:

- `maxHeight`: the height of the scroll area, in pixels or as a CSS length. Defaults to 480.
- `estimateSize`: the height of one row, in pixels. Defaults to 40. Rows are not measured, so set it to the height your rows have, and keep them that height: the demo stops its cells from wrapping with `slotProps.cell`, so a narrow screen scrolls the table sideways instead of growing the rows.
- `overscan`: how many rows to render beyond the visible ones, so a fast scroll shows no blank space. Defaults to 10.

Pagination is off by default; [`enablePagination`](../../api/#props) turns it back on. The table is compact (`size="sm"`) unless you pass `size="default"`.

Everything else works as in `DataTable`: [sorting](../sorting-and-selection/), selection, [tree rows](../tree-rows/), the loading, empty and error states, labels and every slot. Rows above and below the window are stood in for by empty spacer rows, so the native table layout, and every `Row` and `Cell` slot, stays as it is.

[Row reorder](../row-reorder/) and [spreadsheet mode](../spreadsheet/) work too. A dragged row stays rendered while it is scrolled out of the window, and the view scrolls under it near the edges; the keyboard scrolls to the row it moves to.

`VirtualDataTable` from `slotsmith/virtual` is the same table with `useVirtualizer` already passed in, for code written before `virtual` took the hook.

## Your own layout

With `virtual`, `DataTable` is `DataTable.Provider` with a virtual body. To place the parts yourself, render `DataTable.VirtualBody` as the `body` of `DataTable.Table`, with the hook as `use`. Keep the scroll area in state with the table's `scrollRef` (a callback ref such as a state setter), and pass that element to the body as `scrollElement`.
