The slotsmith Autocomplete is a React combobox and select in one component: it filters as you type, or works as a plain select with typeahead. It takes one value or several, remote options, a create row and virtual lists. Every part it renders is a slot you can replace.

## Overview

The demo below uses the fallbacks only. Open a picker with the mouse or with <kbd>↓</kbd>, type to filter, and pick with <kbd>Enter</kbd>. The topics picker keeps several values as tags; its last topic is archived and cannot be picked.

## Adapters

The autocomplete works with any design system. Each slot takes a component, so a library's own popover surface, input, tag and menu item can replace the fallbacks. The [Adapters page](./adapters/) has ready slot maps for shadcn/ui, MUI, Chakra, Ant Design and Radix Themes, as examples of well-known libraries; the same approach works with your own.

## Accessibility

The autocomplete follows the ARIA combobox pattern, with the listbox in a popup:

- **The trigger** is the element with `role="combobox"`. It is in the tab order, and carries `aria-expanded`, `aria-haspopup="listbox"` and, while open, `aria-controls` pointing at the list. The naming and validation attributes you pass to `Autocomplete` (`aria-label`, `aria-labelledby`, `aria-describedby`, `aria-invalid`, `aria-required` and the like, plus `id`) go to this element, not to the wrapper.
- **The search box** gets focus when the popup opens. It has `role="searchbox"`, `aria-autocomplete="list"`, and is named by the [`search`](./api/#label-search) label. See [select or combobox](./guides/select-or-combobox/).
- **Search in the trigger.** With `searchIn="trigger"` the combobox is an input inside the trigger, the WAI-ARIA 1.2 editable combobox. It carries `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, `aria-activedescendant` and the naming props, keeps focus while the list is open, and a `<label for>` names it. The chevron is a button outside the tab order, named by the [`toggle`](./api/#label-toggle) label. See [search in the trigger](./guides/search-in-trigger/).
- **The highlight** is announced through `aria-activedescendant`: on the search box, or on the trigger itself when `searchable` is `false`, so focus never leaves the field while you move through the options.
- **The list** has `role="listbox"`, with `aria-multiselectable="true"` in multiple mode and `aria-busy="true"` while `loading` is set: with `useAsyncOptions`, while each search loads its first page, even when the last options still show. Loading more at the end of the list does not set it. Each option has `role="option"` and `aria-selected`; an option ruled out by `optionDisabled` has `aria-disabled="true"` and the arrow keys skip it. See [multiple values](./guides/multiple/).
- **Groups.** With `getOptionGroup`, each group has `role="group"` and is named by its label through `aria-labelledby`. The line between groups is hidden from assistive technology. See [groups and separators](./guides/groups/).
- **Invalid values.** `invalid` sets `aria-invalid="true"` on the combobox, never on the popup's search box. Point it at your error message with `aria-describedby`. See [validation](./guides/validation/).
- **Result counts** are read out: a visually hidden `role="status"` region (`aria-live="polite"`) says "12 results" as the list changes, from the [`results`](./api/#label-results) label. It is empty while the popup is closed or shows a status row. See [remote options](./guides/remote-options/).
- **Tags and clearing.** Each tag's remove button is named by the [`remove`](./api/#label-remove) label ("Remove Forms"), and the clear button by [`clear`](./api/#label-clear). Spinners are hidden from assistive technology. See [the states](./guides/states/).

## Limitations

<Note kind="limitation">
- It does not fetch. `Autocomplete` renders the options you pass; [`useAsyncOptions`](./guides/remote-options/) calls your own `load` function.
- No inline completion: the input never fills in the rest of the top match as you type. For that, or for a command palette, build on the [`useAutocomplete`](./guides/compound-parts/) hook.
- Groups are one level deep and take their order from the options; there are no nested groups. See [groups and separators](./guides/groups/).
- The "Load more" and "Retry" buttons in the list are reached with the pointer only: the keyboard stays in the search.
- An option's label is a string, because the trigger, the filter and typeahead read it. A richer row goes in the `OptionLabel` slot. See [remote options](./guides/remote-options/).
- The popup renders in place by default, with `position: fixed`, so it escapes `overflow: hidden` and makes up for an ancestor with a `transform`. Pass [`portal`](./api/#props) to render it in `document.body` or an element of your own; set the `--ss-*` tokens and the dark class on `:root` or that element, which the popup then inherits from.
</Note>
